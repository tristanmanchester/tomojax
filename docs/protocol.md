# Local worker protocol

Protocol 1 uses UTF-8 JSON Lines. The client writes one request per line. The worker writes reply headers on stdout and reserves stderr for diagnostics. A pixel block header has a binary body. All other replies end at the newline. The first line is `ready`. Its device IDs are the values to send in operation parameters. Its capabilities name supported top-level command tags. The versioned schemas and fixed conversations in [protocol/](protocol/) are the client contract. Resolve their absolute schema IDs to local files when validating offline.

A request has a unique string `id`, a tagged `command` and an optional `channel`. `type` selects the variant of a command, workflow, product or storage reference. Required fields and defaults are in the schemas. Omitting a defaulted field uses its declared default. An explicit null is valid only for a nullable field.

The `describe` response contains a JSON Schema in `result.parameters`. Its `$defs` describe the inputs to each operation. Form controls can read `description` for help, `x-choices` for canonical domain choices, and `x-unit` for the unit of a value. `geometry_length` uses the scan's length unit. `native_pixel` and `working_pixel` refer to the original and working detectors. The `x-python` table maps public Python arguments to wire fields. A worker-owned argument such as the reconstruction output buffer is allocated by the executor.


Each admitted request receives zero or more `progress` envelopes followed by one `result` or `error`. Match all three by `request`. Each echoes `channel: null` or the channel name and its monotonically increasing revision. When replacing work on a channel, drop progress and artifacts from older revisions, including records already in the pipe. A rejected line receives a separate `protocol_error` of kind `invalid_request`. Its `request` echoes every readable string ID, including an invalid ID on a rejected command. It is null when the worker cannot decode a string ID. A duplicate ID leaves the original request pending. Unexpected EOF before a terminal means the process or connection was lost.

## Inputs and outputs

`{"type":"path","path":"scan.h5"}` opens a source on the execution queue. A handle member uses `{"type":"member","handle":"h","member":"self"}`. Every root has a `self` member. Named members are direct lookups in the owning result. For example, pass an alignment's `scan` member wherever a scan is accepted. The session pins every referenced member at admission, including refs in configs and correction steps. It also pins referenced session artifacts. Closing a handle prevents further admissions against it. Admitted work retains its inputs through completion.

Columns below name accepted input kinds in addition to the options defined by the indicated schema variant. A path used as a scan runs the normal scan loader. Raw calibration stays with a frames handle. Opening by kind explicitly selects the saved-data loader. Bulk inputs use storage references, including masks, exposure arrays and pose tables.

Products carrying a scan report its correction history in `info.summary.corrections`, in the same order as Python's `scan.corrections`. Each record contains `name`, `settings`, and `found`. A bulk numeric value appears as `null` with a matching JSON pointer in `info.arrays`.

Execution results include bounded `info` and an input manifest. Each manifest node identifies the operation, its parameters and its ordered inputs. File roots retain the source path. Include all contributing inputs even when two distinct members come from the same root. Save and export write the returned manifest at `<destination>.manifest.json`. Raw, MetaImage and AmiraMesh exports also write an adjacent record at `<destination>.json`. The owner commits these paths together. Force permits replacement of an existing output. Opening an input records its physical files in the worker process. These include HDF5 external-link targets, virtual dataset sources, external raw storage, vendor metadata, individual frames and separate calibration files. Files stay protected while a running operation, open handle, unreleased artifact or reachable Python result depends on them. A dry run releases its inputs when it returns or raises. All durable destinations, sidecars and checkpoint directories are checked against the live inputs by name and filesystem identity, including symlinks, hard links and directories containing a protected file. A conflict identifies the input and calls for a different destination, even with `force`. The worker registers handles and publishes terminals. Its committer owns durable destinations. Session artifacts live until release, owning-handle close or shutdown. Input files and committed durable destinations belong to their caller.

A format-2 dataset includes the worker operation and its input lineage in the
JSON document at `/entry/record`. A slab reconstruction adds the resolved
solver settings when the final slab has been written. Saved array references
name the HDF5 signal. The scan signal has axes `(view, v, u)`, and volumes,
working images and phantoms have axes `(z, y, x)`.

## Fetching a plane

Give `fetch` the storage and shape from the array descriptor. It reads on the I/O threads while the executor works or waits. This request selects every second sample of a volume plane.

```json
{"id":"p1","channel":"axial","command":{"type":"fetch","storage":{"type":"hdf5","path":"volume.nxs","dataset":"/entry/volume/data"},"shape":[100,1024,1024],"roi":[[7,8],[0,1024],[0,1024]],"stride":[1,2,2],"encoding":"jpeg","window":[-2,2]}}
```

Supply half-open bounds and positive strides in descriptor order. A stored line detector with shape `(view,u)` can use its registered shape `(view,1,u)`. The result keeps the singleton axes. Use the descriptor for coordinates and units. The decoded plane can occupy up to 16 MiB.

For `jpeg`, the worker maps the two window limits to grey levels 0 and 255, clips outside values and encodes an 8-bit grayscale JPEG at quality 60. A null or omitted window selects the finite minimum and maximum. A zero-width window or a non-finite sample maps to level 0. The terminal reports the window in `range`. For `float32`, decompress the frame with zstd. The four consecutive byte planes hold byte 0 of every little-endian float, then byte 1, byte 2 and byte 3, in C sample order.

When a header such as `{"type":"block","request":"p1","bytes":65536}` arrives, consume the newline, then read exactly that many bytes. The next header starts immediately afterward. Append the bytes to the named request and send `{"credit":65536}` on its own line to return the number consumed. Credit starts at 262,144 bytes across all requests. Each block carries at most 65,536 bytes. Credit lines have no ID or reply.

The worker sends pending JSON replies first. For each block it selects the ready frame with the fewest bytes remaining. Decode a frame when its successful terminal reports its shape, encoding and total byte count. A newer request on the same channel drops unsent blocks of the earlier fetch. Discard any partial frame on a `superseded` error and return credit even for bytes you discard. Up to eight off-channel fetches may be active. A fetch ID becomes available again after its terminal and does not count toward the session ID limit.

## Progress and array registration

Feature bands reuse mask indices directly. The source and feature must have equal shapes, ordered axis names, frames, axis units and fixed-plane coordinates. Origins, signed pitches and all sample centers (including explicit coordinate vectors) must agree within an absolute `1e-6` in each axis's declared unit. A mismatch returns the differing field and a remedy, even for disjoint grids. Choose a feature on the target grid or resample it explicitly before submission. The same rule applies to registered support masks on the resolved reconstruction grid and registered inputs to projection and backprojection. A saved volume path supplies logical `(z, y, x)` order for projection. An explicit volume dataset keeps its stored axes. Bare numerical inputs to those operators take their registration from the operation.

A band selects voxel centers with `inner < distance <= outer` in Euclidean index units. Inside the feature, distance is one minus the distance to the nearest background center. Every voxel beyond the grid is background, so a face adjacent to the exterior has distance zero. Outside the feature, distance is measured to the nearest feature center. Both bands return only voxels within the source grid. An empty selection reports zero voxels and null mean and standard deviation.

A metadata-only `read` returns a `layout` with no pixel storage. Each nonuniform axis includes a session npy holding its complete coordinate vector. Release each coordinate artifact after use.

A center sweep resolves `region` once on the input scan. Every center uses that grid, its support and the same plane index. To reproduce a plane, shift the detector to the requested horizontal offset in input detector pixels and run a full reconstruction with the resolved `grid=`. Keep the resolved cylinder mask when requesting cylindrical support. All planes share one spatial registration, including repeated centers.

The Python functions in `tomojax.interactive` are `reconstruct_slice`, `reconstruct_slices` (several planes, sharing one full reconstruction when any needs it), `center_sweep`, `correction_preview` and `region_preview`. Correction previews express the requested row interval on the binned detector. At binning factor two, `[1, 3)` returns native rows 2 through 5 in `before` and binned rows 1 and 2 in `after`. Each array carries its own pixel-center coordinates and view angles. The `views` array gives the positions retained from the input acquisition. Region bounds are voxel edges in physical x, y, z order. Each overlay records the index and physical coordinate of its central plane.

The standalone v2 progress schema covers task start/end, completed work with nullable ETA, placement, notes, pause/resume, previews and CLI terminals. A note carries the innermost open task ID, or null for a watch-level message between operations; a log message repeated within one operation becomes one note. The worker's `progress.record` admits only nonterminal events. `placed` lists actual participating devices. Elapsed time and ETA use seconds. Error kinds are `input`, `invalid_parameter`, `out_of_memory`, `canceled`, `superseded` and `internal`; a `canceled` error from a checkpointed run carries `checkpoint` naming its directory. Worker admission errors have their own envelope. A failure path such as `corrections[2].alpha` starts at the operation's parameters.

Every descriptor carries shape, NumPy dtype, ordered axes, value unit/domain and storage. `npy` names a file, `hdf5` names a file and dataset, and `member` names a session handle and member. Session-produced npy files carry a release token. Client-owned npy and HDF5 inputs stay caller-owned. Array values travel outside JSON. Each axis gives a name, frame, unit, and either uniform coordinates or a reference to a one-dimensional vector of its coordinates. Coordinate order equals stored index order, including for irregularly selected views.

Volume dimensions are (z, y, x). A uniform origin locates the **center of the first voxel** in that dimension. A removed axis records its source index and physical coordinate in `fixed`. Projection dimensions are (view, v, u). Poses are in the detector frame with columns (alpha, beta, phi, x, z, y), the first three in degrees and the last three in the scan's length unit. Lengths can be in pixels for uncalibrated data. Values distinguish counts, transmission, line integrals, attenuation and mixed-unit pose columns.

The compact UTF-8 encoding of `info` is limited to 65,536 bytes. Bulk members are externalized before scalar JSON conversion. Their positions in `summary` are null and their descriptors are in `arrays`, keyed by RFC 6901 JSON Pointer (including `/disturbed_views/score` and `/disturbed_views/ranges` or `/disturbed_views/angles` when longer than 64 entries). The scalar summary retains method selection details such as `automatic`, truncation diagnostics (`truncation`: `edge_ratio`, `outside_fraction`, `interior_shift`, `radius`, `field_of_view_radius`, plus `outside_grid`, `data_model`, and `background_treatment` for iterative methods) on `run.reconstruct` and `run.reconstruct_slabs`, solver stopping fields (`termination`, `early_stop`, `effective_iterations`, `resolved_tv_weight`, `noise_score_rms`, `measurement_noise_rms`, `projection_error_rms`, and `slab_stopping` on independent axial iterative slabs), alignment `calibration`, `diagnostics`, `disturbed_views`, and `fit_views` (when views are excluded), and reader statuses in `geometry` (`detector_center_status`, `geometry_status`, and `frame_records`). All seven method configs (`FBPConfig`, `FourierConfig`, `CGLSConfig`, `FISTAConfig`, `SPDHGConfig`, `SIRTConfig`, and `MLEMConfig`) accept `exterior` as `"cylinder"` (default) or `"zero"`.

## Python hand-off

Decode a line as `tomojax.cli.envelope.Request`. For a queued command the adapter receives its typed `ExecutionInput` and an `ExecutionContext`. The owner resolves and pins the input references before queuing and supplies the leases, control, event sink, immutable allocator snapshot sink and private staging allocator. Adapters return `Success` or raise. They may only write to paths supplied by staging. An array reservation has distinct private and eventual public paths. Output reservations within one admission form a durable group, including manifests.

A returned `NewHandle` gives logical bytes, a pure `bind(id)` returning the published product and member map, and a disposal callback. The owner assigns the ID and checks the channel revision at commit. Losing the race discards staged files and unpublished resources. Disposal after successful registration waits for the last lease. The owner emits all worker terminal envelopes.

## Driving the process

Start `tomojax serve` with stdin and stdout pipes. Read `ready` before submitting commands and use its capability list for this build. Read stdout concurrently with writing stdin. The worker samples the device inventory at startup and answers `describe`, `devices` and `status` from memory. Allocator samples come from the executor. An empty allocator list means no sample has arrived. The latest sample for each (device, scope) includes its own timestamp. Handle sizes are logical bytes.

Send at most 1 MiB of UTF-8 per request line, excluding its newline. Request and channel IDs are limited to 256 UTF-8 bytes. Up to 64 execution requests may be active or queued. A replacement that displaces a queued admission can enter a full queue. Immediate commands still work at the queue limit. Use a fresh process after 100,000 admitted IDs. Shutdown remains available at the ID limit. An unknown member, mismatched artifact token and path, duplicate ID, unavailable command or exhausted admission limit yields `protocol_error`. A rejected replacement leaves the prior channel revision in effect.

Queued commands run in arrival order. A later admission on the same channel increments its revision, removes queued predecessors and wakes a running predecessor. Cancellation of queued work ends it immediately. Running work stops at a cooperative work boundary (an iteration, slab, or batch), or at publication if it returns first. Pause moves running work through `pause-requested` to `paused` at that boundary. Pausing holds the run in memory and does not write restartable state to disk. A run given `checkpoint` saves its state there: periodically, and at the boundary where a cancel, a superseding admission, shutdown or `SIGTERM` stops it. Its terminal is then a `canceled` error whose `checkpoint` names the directory; the same operation with that checkpoint resumes, and `inspect` on the directory reports what it holds and the operation and input provenance that started it. Resume withdraws a pending pause or wakes a paused request. A paused request holds its memory and the execution queue. Send `control` or `status` off-channel when observing existing work.

The writer preserves record order. Consecutive pending `advanced` events for one request and task may collapse to the newest event. Previews and their coordinate files are published before their record and stay available for release, including when a newer revision supersedes the job. The worker discards stale preview callbacks and disposes of their private reservations when the adapter exits. A partially written line always finishes before another begins.

On shutdown, stdin EOF or `SIGTERM`, the worker closes admission, cancels outstanding work, wakes paused requests and joins the executor. Keep draining stdout through EOF to receive every terminal, including those after the shutdown acknowledgment. Broken stdout, more than 16 MiB of queued JSON lines in addition to the line being written, or two seconds without any writable pipe capacity during final drain means connection loss. The process exits with status 1 after cleanup. A draining client gets status 0. After an unexpected EOF, use the filesystem to check durable destinations whose terminals were lost.

## Durable files

Save, export and slab reconstruction adapters reserve a private staging location on the destination filesystem for each file or directory, including sidecars and manifests. The session serializes admission and publication. Cancellation or a higher channel revision admitted before the commit check discards the entire group and preserves existing destinations even with `force`. Once the session enters commit, it finishes the group and queues its terminal before admitting another command. Sending bytes on stdin alone does not establish which command won.

Without `force`, an existing group member causes the commit to fail. With `force`, originals move to private backups while the group is installed. A missing manifest, failed rename or other install error rolls back earlier group members and returns an error. A failed restoration reports the location of the retained original for recovery. Use the successful terminal as the point to open all files. Other filesystem readers can observe individual renames during a group commit. Concurrent external writers and process or machine crashes have no multi-file transaction guarantee.

Release takes only the issued artifact token. A successful release or handle close rejects new references immediately. Earlier admissions retain their leased storage through their terminal. Normal shutdown removes remaining private and published session files. Committed outputs remain caller-owned.

## Standalone commands

Set `previews: true` on a `run` request to receive completed work boundaries as `preview` records. Reconstruction and alignment images contain central `z`, `y` and `x` planes. Alignment also reports per-view pose increments in the acquisition convention. Correction previews carry `before` and `after` sinograms on their own detector grids. An axis coordinate vector is itself a session artifact. Release these files after displaying them. Intermediate frames are limited to one per active second. The last completed state is delivered at the end, including early stopping.

In Python, pass `previews=True` to `progress.watch` to receive small host arrays. To write a standalone JSON preview, pass the consumer directory to `progress.to_json(event, directory=path)`.

An indeterminate `prepare` task brackets work on the calling thread that can include cache lookup, lowering, compilation or first execution. A warm run can report the same task.

Pass `--progress json` to inspect, correct, reconstruct, align, simulate or export. Read one JSON object per stdout line. A successful invocation ends with `result`. Its `outputs` list includes each written file, and its `arrays` reference the stored data. Export reports the source volume in disk axis order and lists the converted files and sidecar. Commands that write a scan-carrying product (`correct`, `reconstruct`, `align`, and `simulate`) return the scan's correction records in `info.summary.corrections`. Inspect returns its report in `info.summary`; with `--preview-dir` it adds `preview_count` and `preview_listing`, the path of `inspect-previews.json`, which lists every preview, the ordered slice requests and any center sweep. Auxiliary NumPy files for bulk diagnostics or NPZ members are caller-owned and live alongside the output. A scalar summary that exceeds the byte limit reports the number of omitted fields as `_omitted_fields`, giving `automatic`, `placement`, and `disturbed_views` priority over solver histories.

Errors end the stream with `error` (carrying `checkpoint` when a checkpointed run stops). An invalid command line exits 2, an operational failure exits 1 and cancellation exits 130. An internal error also produces a traceback on stderr. A process killed before delivery leaves EOF without a terminal. TomoJAX's own log messages and warnings arrive as `note` records. `reconstruct --watch-dir` and `align --watch-dir` write images and carry no `preview` records in the stream.


### Planning a run

`tomojax reconstruct --dry-run` and `tomojax align --dry-run` print the resolved plan as text without writing an output. With `--progress json` the stream ends with a `result` record whose `info.summary` is the plan; an alignment's adds its input and output paths, fit, method, configuration and grid. `tomojax correct --dry-run --progress json` ends with the steps in run order, the output `shape`, its float32 `bytes`, `upper_bound` (true when view rejection can drop views) and `full_rows` (true when the preview reads every detector row). Reconstruction reports the selected inverse, its reasons, its voxel grid and the configured iteration limit for iterative methods. A joint fit lists the padded working grid, outer iteration limit and image iterations per solve at each level. The returned working image crops the padding. A sinogram focus plan reports the number of interior views, the detector binning for the Fourier slices, and the number of native opposing pairs on a half turn, or twice the opposing angular pair count, binning 1, and the pair count on a full turn. Opposite-views reports how many angular pairs the estimator will examine. Pairs with unusable measured data can subsequently be rejected.

The placement estimate includes the sample timestamp, device identifiers and available bytes. Host and device byte estimates describe the working arrays. CPU availability comes from host memory and its cgroup limit. When CuPy participates in iterative placement, the snapshot includes its reusable pool and free driver memory under the same device ID with scope `cupy`. A volume that stays on the device has strategy `resident` even when projections stream from the host. Compiled temporaries, allocator fragmentation and other processes can affect execution. Read the run's `info.placement` for the participating devices, actual storage strategy and the number of allocation retries by work unit.
